# ISR：DB 構築・画像検索・レンダリング評価

先に **XY 平面上の位置誤差・yaw の差の測り方と、地点単位の DB / dev / test 分割**を固定します。成功判定に使う **2 m・3 m・5 m、角度 30°は仮の分析条件**です。業務上の合格基準は未確定で、閾値は後から変更できます。同じ画像・モデル・前処理・出力先なら、保存した特徴ベクトルを再利用して再集計します。

学習済み MegaLoc を固定して使います。追加学習は行いません。今回の評価対象はレンダリング画像同士の検索であり、実写を入力したときの精度は未検証です。

## 何を返し、何を正解にするか

DB 用画像から MegaLoc の特徴ベクトルを計算し、その画像の ID・撮影座標・向きと対応付けて保存します。入力画像も同じ方法で特徴化し、コサイン類似度が高い順に DB 画像を返します。

返す座標は、**候補として検索された DB 画像の撮影座標**です。入力写真のカメラ位置・姿勢を連続的に推定した値ではありません。類似度も正解確率ではありません。

評価用レンダリング画像には、生成時の本当の撮影位置・向きが JSON にあります。検索には画像だけを入力し、クエリの正解座標・向きは答え合わせにのみ使います。

| 項目 | 定義 |
|---|---|
| 正解情報 | クエリの JSON に記録された撮影位置と yaw |
| 座標系 | UE のワールド座標。左手系、Z が上、X が前。元 JSON の cm を m に変換 |
| 位置誤差 | クエリと候補画像の XY 座標のユークリッド距離。全画像の高さが同じため、このプロトコルでは Z を使わない |
| 向きの差 | `abs((query_yaw - candidate_yaw + 180) % 360 - 180)`。0° と 360°は同じ向き |
| 場所の正解候補 | 位置誤差が距離閾値以下の DB 画像 |
| 場所＋方向の正解候補 | 距離条件を満たし、yaw の差も角度閾値以下の DB 画像 |
| 境界値 | 閾値ちょうどを含む。浮動小数点誤差の許容は `1e-9` |

例えば、距離閾値 2 m のとき、正解位置から 2 m の DB 画像は正解候補、6 m の画像は不正解です。近い候補が複数あれば、いずれも正解候補になります。

今回の画像は yaw が 0°・90°・180°・270°の4方向です。角度差 30°以内という条件は、実質的に「同じ向き」の判定です。yaw の差だけで、共通して見える面積や遮蔽物の有無は評価できません。

## データの分け方

対象 ZIP は、25 地点 × 4 方向の100枚です。同じ地点の4画像はすべて同じ用途に割り当てます。

| 用途 | 地点数 | 画像数 | 使い方 |
|---|---:|---:|---|
| database | 15 | 60 | 検索対象の DB |
| dev | 5 | 20 | 改善方法や設定を選ぶためのクエリ |
| test | 5 | 20 | 固定した最終評価用のクエリ |

既定 seed は 42 です。固定 seed の候補順で、すべての dev / test 地点に 3 m 以内の DB 地点がある分割を選びます。分割の選択には座標だけを使い、画像の特徴や検索結果は使いません。したがって、この評価は **3 m の範囲で DB に撮影地点がある条件**の基準性能です。2 m などの厳しい閾値では、正解候補がないクエリもあり得ます。

準備時に、画像と JSON の対応・寸法・座標・向き、画像の重複を検証します。異なる split に同じ画像や同じ画素内容が入る場合は停止します。保存済みの画像・JSON・分割を変更した場合も、黙って上書きせず停止します。

`data/isr_20261112/images/` には全100枚があります。DB の構築には、`manifest.json` の `split == "database"` の60枚だけを使用します。この画像フォルダ全体を従来のフォルダ検索スクリプトに渡すと、評価クエリまで検索対象に入るので、今回の評価には `isr_pipeline.py` を使用してください。

## 実行環境

PowerShell を、このプロジェクトの `isr_pipeline.py` があるフォルダで開きます。以下の `python` は、PyTorch・torchvision などの必要ライブラリが入った Python を指します。既存 README の仮想環境を使用する場合は、`python` の代わりに `& .\.venv\Scripts\python.exe` を使います。

この作業環境では、既存の学習済みモデルのキャッシュをプロジェクトの `models/` に配置しています。パイプラインはそのキャッシュをオフラインで読み込みます。

新しい PC でモデルがない場合は、[README.md](README.md) の手順1・2で Python と依存ライブラリを用意し、手順4の `megaloc_search.py` を一度実行してモデルを取得してください。この初回準備にはインターネット接続が必要です。別の場所に既存キャッシュがある場合は、`--model-cache "キャッシュのmodelsフォルダ"` を指定できます。

## 1. DB 構築から基準評価まで一括で実行する

```powershell
python .\isr_pipeline.py run --archive "$env:USERPROFILE\Downloads\ISR_grid_200cm_20261112-20261116T115529Z-1-001.zip"
```

このコマンドは順に、データ検証と展開、地点分割、DB 60枚の特徴保存、dev / test 合計40枚の検索、位置・方向による評価、HTML レポートの生成を行います。既定では CPU・batch size 1 を使います。

結果は `output/isr_pipeline/evaluation/report.html` で確認できます。HTML は同じフォルダ内の画像プレビューを参照するため、共有する場合は出力フォルダごと扱います。

同じコマンドを再実行すると、DB とクエリの特徴を再利用します。再利用時は `Reusing database` と `Reusing 40 query embeddings` が表示されます。ファイルの整合性確認、ランキング、集計、レポート生成は再実行されます。

初回は全体の基準性能を測るため test も含めます。その後の改善方法や設定の選択は **dev のみ**で行います。test の結果に合わせて調整を繰り返さず、最終設定を固定してから test を評価します。

## 2. 任意の画像を検索する

`--query` を実在する入力画像のパスに変更します。実写でもレンダリング画像でも入力できます。

```powershell
python .\isr_pipeline.py search --db .\output\isr_pipeline\db --query "C:\path\実画像.jpg" --out .\output\isr_search
```

上位5件の画像・コサイン類似度・候補の撮影座標・yaw を出力します。候補数は `--top-k 10` などで変更できます。

`output/isr_search/report.html` が比較画面です。このコマンドは入力画像の正解位置を要求しないため、成功・失敗や位置誤差を評価しません。実写の位置精度を測るには、実写の撮影位置を UE 座標系に対応付けた正解情報が別途必要です。

## 3. 改善用クエリを評価し、閾値を変更する

```powershell
python .\isr_pipeline.py evaluate --split dev --distance-thresholds 1 2 3 --angle-threshold 30 --out .\output\isr_pipeline\evaluation_dev
```

このコマンドは dev 20枚を評価します。初回の `run` の出力先とは別なので、`evaluation_dev` で初めて実行すると、dev 20枚の特徴を計算して保存します。その後、**同じ `--out` と同じ `--split dev`** のまま閾値だけ変えると、その特徴を再利用します。

```powershell
python .\isr_pipeline.py evaluate --split dev --distance-thresholds 2 3 5 --angle-threshold 45 --out .\output\isr_pipeline\evaluation_dev
```

同じ出力先の集計・レポートは更新されます。比較のため古い結果を残す場合は、実行条件と結果ファイルを別に保存してください。新しい `--out` を指定した場合は、そのフォルダ用のクエリ特徴キャッシュを初めて作ります。

閾値を変えても、類似度による検索順位は変わりません。変わるのは、どの候補を正解と数えるかです。実用上の必要精度と DB の撮影密度をもとに、最終的な合格基準を決めます。

## 評価指標の読み方

| 指標 | 意味 |
|---|---|
| Recall@1 / @5 / @10 | 上位 K 件に正解が1件以上あるクエリの割合。分母は全評価クエリ |
| 条件付き Recall | 正解候補が DB に1件以上存在するクエリに限った Recall。該当クエリが0件なら `null` / `—` |
| Coverage | 正解候補が DB に存在するクエリの割合 |
| 1位の位置誤差 | 全クエリの位置誤差の平均・中央値・90パーセンタイル・最大値 |
| 1位の yaw 誤差 | 全クエリの最小角度差の平均・中央値・90パーセンタイル・最大値 |
| 最寄り DB 地点までの距離 | DB の密度だけで生じる制約。画像検索の順位とは独立に計算 |

DB に正解候補がないクエリも、主集計では失敗として数えます。条件付き Recall と Coverage を併記することで、DB の撮影地点不足と、正解候補があるのに取り違えた検索の失敗を分けて確認できます。成功・失敗を除外せず、件数と率をセットで確認します。

処理時間は、画像の特徴抽出時間と、特徴ベクトルの行列積によるランキング時間を分けて記録します。モデルの読み込み、画像ファイルの検証、レポート生成を含む端から端までの所要時間とは異なります。

| ファイル・フォルダ | 内容 |
|---|---|

`--out` を指定すると、評価・検索の出力先が変わります。画像・モデル・前処理・split が変わった場合、既存 DB の不一致を検出します。元データや split を変える実験は、新しいデータ保存先・DB 保存先を使い、比較対象の結果を残してください。

## 処理を個別に実行する場合

```powershell
python .\isr_pipeline.py prepare --archive "$env:USERPROFILE\Downloads\ISR_grid_200cm_20261112-20261116T115529Z-1-001.zip"
python .\isr_pipeline.py build
python .\isr_pipeline.py evaluate
```

`prepare` はモデルを読み込みません。`build` は既存 DB が一致する場合に再利用し、`--rebuild` を付けた場合は指定 DB の特徴とメタデータを作り直します。各コマンドの全引数は `python .\isr_pipeline.py <コマンド名> --help` で確認できます。
