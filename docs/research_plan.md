## 1. 研究の問いと範囲

### 主な問い

1. 回路ファミリーや規模によって、T-count・2Qゲート数・depthの改善量はどう異なるか。
2. 通常のゲート単位の最適化に対して、ZXを使うことで追加の利益が得られるか。
3. よく改善する例と改善しない例には、どのような構造上の違いがあるか。

Forward／Reverseは、抽出方向によって結果が変わるかを確認する**副実験**として残す。機械学習による方向予測、新しい書換え則の開発、実機ルーティングは今回の必須範囲から外す。

結論は「ZX-calculus一般が効く／効かない」ではなく、**「今回評価したPyZXの処理手順・回路群・コストモデルでは、この条件で改善／悪化した」**と限定する。改善がない結果も研究の対象であり、改善率の達成を実験完了条件にしない。

## 3. 全実験で共通にする比較条件

### 3.1 四つの比較条件

| 条件 | 処理 | 役割 |
| --- | --- | --- |
| Original | 入力を共通の基本ゲートへ分解・正規化 | 最適化前の参考値 |
| Gate-only | Originalにゲートの交換・打ち消し・結合を適用 | ZXグラフを使わない主比較基準 |
| ZX-F2 | Original → ZX変換 → full_reduce → Forward抽出 → 共通のゲート整理 | 主なZX最適化手順 |
| ZX-R2 | ZX-F2と同じ簡約済みグラフの随伴から抽出 → 出力の随伴 → 共通のゲート整理 | 方向を変えた副比較 |

`N`を固定した基本ゲートへの正規化、`B`を固定したゲート単位の整理、`E_2`を設定2の抽出として、処理を次で定義する。

```text
C0 = N(C)
Gate-only = N(B(C0.copy()))
G = full_reduce(Z(C0))  # 元グラフをコピーして扱い、F2/R2で共有する
ZX-F2 = N(B(N(E_2(G.copy()))))
ZX-R2 = N(B(N(adjoint(E_2(adjoint_copy(G))))))
```

主解析では、ZX変換前に片方だけ追加のゲート最適化を入れない。後処理Bの設定・回数はGate-onlyと両ZX候補で同じにする。抽出直後と後処理後を両方保存し、ZX抽出自体の効果と後処理の効果を区別する。

Bの第一候補は `pyzx.optimize.basic_optimization` とし、SWAP関連の設定を含めて小回路で検証してから固定する。QFTの一般角にも同じ処理が安全に使えるか確認する。未対応なら失敗・未対応として記録し、黙って別アルゴリズムへ置換しない。[S1]

### 3.2 固定する項目

- PyZXは既存パイロットの **0.10.8を出発点**とし、動作確認後に依存関係を固定する。これは最新版であるという主張ではない。版を変える場合は新しいprotocol_idで扱う。
- 抽出は `optimize_cnots=2, optimize_czs=True, up_to_perm=False`。Backwardという名称はログ上でReverseに統一する。
- F2/R2は同じ簡約済みグラフの独立コピーから生成する。方向ごとに別の回路を簡約する旧方式は混ぜない。
- 測定・リセットのないユニタリ回路を対象とし、入力・出力の量子ビット順を固定する。
- 主な論理2Qコストは **CNOT数＋CZ数**。Toffoli・SWAP・制御回転の分解規約を固定し、残ったゲートを機械的に検査する。`to_basic_gates()`だけで目的の基底に揃ったと仮定しない。
- Clifford＋T回路はH、S/S†、T/T†、CNOT、CZなどへ厳密に正規化し、TとT†を両方数える。CNOT-only基底へ変えた場合はdepthも変わり得るため、別gate_basis_idとする。
- depthは同じ基底での論理的な依存段数。runtimeは古典計算機での最適化時間。実機での速度・誤り率を測定したことにはしない。

## 4. 第1段階：幅広い回路比較

### 4.1 最初の入力セット

以下を**実行前に固定する初期案**とする。生成器、長さ、角度、シードなどをマニフェストへ書き、小規模な動作確認を終えてから33入力全体を実行する。

| ファミリー | 条件 | 入力数 | 主な確認点 |
| --- | --- | ---: | --- |
| QFT | 4・6・8量子ビット | 3 | 規則的な制御回転構造の2Q・depth |
| Toffoli ladder | 4・6・8量子ビット | 3 | T削減と2Q増加の関係 |
| 位相回路 | 4・6・8量子ビット × 3シード | 9 | CNOTと位相操作の配置・重複 |
| 反復Pauli回転回路 | 4・6・8量子ビット × 反復数2・4・8 | 9 | 同じブロックの反復と最適化効果 |
| ランダムClifford＋T | 4・6・8量子ビット × 3シード | 9 | 不規則な構造との比較 |
| **合計** |  | **33** |  |

ランダムな2ファミリーの初期シードは0・1・2を案とする。ランダムClifford＋Tは `CNOT_HAD_PHASE_circuit`、生成引数depth=80、`p_had=p_t=0.2`を出発点とし、生成引数のdepthと計測した回路depthは区別する。

位相回路はCNOTとπ/4の整数倍の位相ゲートで作り、ゲート数・位相比率・接続の選び方を固定する。反復Pauli回転はブロックの演算順、作用対象、角度を固定し、Clifford＋Tで厳密に表せる角度を使う。単純な逆演算の連続挿入だけで改善を作った回路は、動作確認用として主結果から区別する。

Toffoli ladderは既存の重なり合う3量子ビットゲート列を出発点とする。これは算術回路全般の代表ではない。Pauli回転の合成回路も、実際の化学計算の性能を代表すると主張しない。サイズとともにゲート数も変わるため、第1段階だけで構造の因果効果を断定しない。

**33入力×4条件＝132行の主比較表**となる。Originalを含む集計であり、独立した132回路ではない。ZX抽出は33入力×2方向＝66候補条件で、時間計測の反復は別に記録する。

### 4.2 QFTの扱い

教授の「16個のFFT」が16点か16量子ビットかは未確定。量子回路ではQFTとして扱い、まず16点に対応する4量子ビットを含める。n量子ビットQFTは2^n次元なので、16量子ビットとは区別する。[S2]

QFTの一般角回転を、Clifford＋Tへの近似合成をせずにTゲート数へ換算しない。一般角に対するPyZXの`tcount()`を、そのまま実装に必要なT-countと解釈しない。[S3]

- QFTの主指標は2Q・depth。非Clifford回転数は定義を固定した補助指標として保存する。
- QFTのT-countは `null / N/A` とし、0で埋めない。Clifford＋T回路のT削減率と平均しない。
- 末尾のビット順反転・SWAPを含むかを固定し、入出力の意味を全条件で揃える。
- QFTのClifford＋T近似合成、16量子ビットへの拡張は、初期実験の必須範囲から外す。

## 5. 第2段階：対照例の詳細検証

### 5.1 何を明らかにするか

第1段階は「どこで差が見えたか」を探す段階。第2段階は「その差は新しい入力でも再現するか」「構造を変えたときに傾向が変わるか」「差は簡約・抽出・後処理のどこに関係するか」を調べる。

例を選ぶ主基準は **ZX-F2対Gate-only** とする。R2で最もよかった例だけを拾ってZX全体の効果としない。R2の効果は別の対応比較として示す。

### 5.2 追加実験の初期案

| 対象 | 変える要因の例 | 揃える条件 | 得たい証拠 |
| --- | --- | --- | --- |
| よく改善した位相系 | 同じパリティへの位相操作の重複、配置、CNOT接続 | 量子ビット数、入力T数・2Q数などを可能な範囲で一致 | 重複や配置が改善と関係するか |
| 悪化したToffoli系 | ゲートの重なり方、接続、順序 | 量子ビット数、Toffoli個数、分解法 | どの構造で抽出後2Q増加が強まるか |
| 反復回路 | 反復数、ブロック順序 | ブロック、角度、量子ビット数 | 反復と追加改善の関係 |
| 方向で差が出た回路 | 元の向き／随伴、必要なら抽出設定2／3 | 共通グラフ、後処理、基底 | 方向・設定が傾向を変えるか |

この表は仮説候補であり、特定ファミリーが必ず有効・無効であるという予測ではない。初期案として主な対照群を2つ選ぶ。乱数を使う群は未使用シード10個（例100〜109）、決定的な回路は複数の新しいサイズ・構造条件を用意する。具体的な件数はS1-7で計算資源に合わせて固定する。同一回路の繰返し計測を新しい入力として数えない。

構造要因の比較では、可能なら入力ゲート数と量子ビット数を揃える。揃わない要因は表に記し、「回路ファミリーの違いだけが原因」と断定しない。探索済みの33入力で仮説を作った後、その同じ入力だけで仮説が確認されたとしない。

## 6. 評価方法と失敗の扱い

### 6.1 有効性の分類

Clifford＋T回路では、Gate-onlyを基準としてT-countと2Qを組にして分類する。depthとruntimeは副指標として必ず併記する。

| 分類 | T-countと2Qの関係 |
| --- | --- |
| 両立改善 | 両方とも増えず、少なくとも一方が減る |
| トレードオフ | 一方が減り、他方が増える |
| 不変 | 両方とも変わらない |
| 悪化 | 両方とも減らず、少なくとも一方が増える |

この分類はTと2Qに限ったものであり、depthやruntimeも優れることを意味しない。QFTはTを使わず、2Qとdepthについて別に分類する。

指標XのGate-only基準の削減率は、`100 × (X_Gate-only − X_ZX) / X_Gate-only`。正なら改善、負なら悪化。基準値が0なら削減率はN/Aとして絶対差を示す。Original比とF2/R2差は別の列にする。

T-countが増えた候補や2Qが悪化した候補も削除しない。後で「Tを増やさない候補から最良を選ぶ」分析をする場合は、条件付き副解析であることと、全候補の結果を併記する。

### 6.2 正しさと実行時間

- 各出力を正規化前の元回路と比較し、Originalへの分解自体も検証する。4〜8量子ビットでは固定順序の行列比較を基本とし、絶対値1の全体位相だけを許す。
- 許容誤差の初期案は `atol=1e-9, rtol=0`。残差、位相の扱い、検証方式を保存し、数値的確認と厳密な証明を混同しない。
- `passed / numeric_mismatch / inconclusive / extraction_error / timeout / unsupported`を区別する。基準となるGate-onlyが未検証の入力は主な削減率集計から分離し、全入力の網羅率には残す。
- 時間計測はウォームアップ後の10反復を初期案とし、本実行前に固定する。処理順を交互・無作為化し、全反復値と中央値・範囲を保存する。反復数は独立入力数ではない。
- 変換、簡約、コピー／随伴、抽出、後処理、検証の時間を分ける。候補ごとの時間と、F2/R2両方を試す戦略全体の実測時間を区別する。共有の簡約は戦略全体で一度計上する。
- 採用する出力そのものを検証する。時間反復の出力を検証済み出力と同一とするならハッシュ等を確認する。同じT・2Q・depthだけでは演算の一致を保証しない。
- 条件ごとの結果を逐次保存する。途中で失敗しても全体を失わず、既存CSVを上書きしない。小規模試行でタイムアウト・メモリ上限を決めて保存する。

第1段階の各ファミリー3シードは傾向探索であり、一般的な改善確率を精密に推定するには少ない。第2段階で区間推定する場合も、回路単位・構造的な関連を考慮し、時間反復を標本数に加えない。

## 7. 結果のまとめ方と卒論構成

### 必ず作る成果物

| 成果物 | 中身 | 何を伝えるか |
| --- | --- | --- |
| 全入力比較表 | Original／Gate-only／ZX-F2／ZX-R2、T・2Q・depth・時間・検証 | 何を試し、何が起きたか |
| ファミリー別集計 | 改善率の中央値・範囲、分類件数、失敗数、分母 | 特定の最大改善例だけに依存しない傾向 |
| T削減率×2Q削減率の散布図 | Clifford＋T回路をファミリー別に区別 | 両立改善とトレードオフ |
| QFTの別図 | 量子ビット数ごとの2Q・depth | 一般角回路をT-countと混同しない比較 |
| 対照例の図と説明 | 入力、ZX簡約、抽出、後処理の対応 | どの構造・処理が差に関係するか |
| 再現手順 | 環境、コード版、入力、設定、生ログ、集計方法 | 同じ結果を再確認できること |

### 英語の結果表の列

```text
Circuit ID | Family | Qubits | Method | T-count | Non-Clifford rotations |
2Q count | Depth | Optimization time | Verification | ΔT vs Gate-only |
Δ2Q vs Gate-only | Effect category | Run ID | Notes
```

### 卒論の章立て

1. **Introduction** — なぜ回路依存性を調べるか、研究質問と対象範囲。
2. **Background and Related Work** — ZX書換え、回路抽出、既知の2Q問題。単に回路ごとに違うという現象だけを新規性としない。
3. **Methods and Experimental Setup** — 4条件、基底、入力生成、検証、計時、二段階の役割。
4. **Broad Benchmark Results** — 全体比較、ファミリー別の効果、悪化・失敗。
5. **Contrasting Case Studies** — 対照例、新入力の再検証、構造要因と処理過程。
6. **Discussion and Conclusion** — 有効条件、限界、代替説明、今後の課題。

結論の書き方の型は「本実験の手順では、条件Aで指標Xの改善が観測された。一方、条件Bでは指標Yが増加した。追加実験は要因Zとの関係を支持した／支持しなかった。ただし適用範囲は対象回路・サイズ・基底に限られる」とする。未実測のA/B/Zや改善率は埋めない。

各行に `run_id, experiment_datetime, timezone, circuit_id, family, qubits, seed, generator_parameters, input_hash, protocol_id, gate_basis_id, method, pyzx_version, code_commit, T_count, 2Q_count, depth, verification_status, error`を残す。QFTなどにはT-countが定義されない理由と、非Clifford回転数の定義を記録する。実行日時とGitHubへのcommit日時は区別する。

日誌は英語の `Goal / Experiment / Results / Discussion / Next Actions` を使い、S1-1やS2-3などの作業IDを添える。計画・実行済み・過去の証拠を区別する。完了チェックの根拠はファイルパス、run_id、commit SHAで示す。
